# ICT活用能力テスト 先生向けガイド

このテストは、受験者が「今の自分のICT活用能力」を知るための、級別・階段型のテストです。
ブラウザだけで動き、ログインやサーバーは使いません。結果は生徒がCSVファイルとして保存し、Teams／OneDriveで提出します。

---

## 1. テストのしくみ

| 項目 | 内容 |
|---|---|
| 級 | 8級（小1めやす）〜1級（高校卒業〜大人めやす）の10段階：8・7・6・5・4・3・**準2**・2・**準1**・1級 |
| 1つの級 | 9問（基本操作・情報収集・モラル安全から3問ずつ、ランダム出題） |
| 合格条件 | **合計7問以上 正解 かつ 各分野2問以上 正解** |
| 進み方 | 選んだ級から始め、合格すると次の級へ。不合格になったらそこで終了 |
| 制限時間 | 全体で30分。30分を過ぎたら、解いている級を最後まで解いた時点で終了 |
| 端末 | 基本操作の問題は端末で切り替え（PC・Chromebook → キーボード・マウス／iPad・スマホ → タッチ） |
| ふりがな・読み上げ | 8級〜6級は問題文にふりがなを付け、読み上げボタンを表示 |

### 採点のきまり
- 「当てはまるものをすべて選ぶ」「並べ替え」「組み合わせ」は、**すべて正しいときだけ1問正解**です（部分点はありません）。
- 文字入力の問題は、**制限秒数以内に、表示された文字を正確に入力して確定**できたら正解です。全角・半角の英数字やスペースの違いは同じとみなします。
- 擬似画面の問題（右クリック・長押し・ドラッグ・ショートカットキーなど）は、操作した結果で判定します。
  - ショートカットキーの問題は、**最初に押した Ctrl＋キーの組み合わせ**で判定します。
  - コピー＆貼り付けの問題は、実際に「貼り付け」の操作をしたときだけ正解です（手で打ち込んだ場合は不正解）。

## 2. 配布のしかた

### 2-1. ファイルを用意する（開発担当の先生向け）

```bash
npm install
npm run build
```

`dist/` フォルダーに次の2つのファイルができます。どちらも**1つのHTMLファイルの中にすべてが入っている**ので、このファイルだけで動きます。

| ファイル | 用途 |
|---|---|
| `dist/index.html` | 受験アプリ（生徒に配る） |
| `dist/teacher.html` | 先生用ツール（生徒には配らない） |

### 2-2. 生徒に開かせる方法（どれか1つ）

1. **GitHub Pages などの Web サーバーに置く**（いちばん確実。iPad でもURLを開くだけ）
2. **学校のファイル共有・OneDrive に `index.html` を置き、ブラウザで開く**
   - PC・Chromebook では、ファイルをダブルクリックして開けます（`file://` で動くように作ってあります）。
   - iPad では、ファイルアプリからHTMLを開くとプレビュー表示になりボタンが動かないことがあります。iPad で使う場合は 1. の方法をおすすめします。

### 2-3. 本番モードと試作モード

| モード | 開き方 | 出題される問題 | 画面表示 |
|---|---|---|---|
| 本番 | そのまま開く（`index.html`） | 先生が確認済み（`approved`）の問題だけ | 通常 |
| 試作 | URLの最後に `?mode=trial` を付ける（`index.html?mode=trial`） | 確認前（`draft`）の問題もふくむ | 画面上部に「試作モード」の帯 |

- 本番モードで、承認済みの問題がその級・分野で3問に足りないときは、その級は「準備中」と表示されて選べません。
- **配布直後はサンプル問題がすべて `draft`（未確認）なので、本番モードでは受験できません。** 問題を確認・承認してから本番で使ってください（「6. 問題の追加と確認」参照）。
- 試作モードの結果は、CSVの `mode` 列が「試作」になり、先生用ツールでも区別できます。

### 2-4. クラスの選択肢を変える

クラスの一覧は `src/config.ts` の `CLASSES` で決めています（初期値は `1-1`〜`6-4` と「その他」）。学校に合わせて書き換え、`npm run build` し直してください。出席番号は `MAX_NUMBER`（初期値 45）までです。

## 3. 授業での流れ

1. 生徒が受験アプリを開き、**クラス・出席番号・はじめる級**を選ぶ（名前は入力しません）。
   端末の種類は自動で判定されます。違っていたら生徒が手で直せます。
2. 級ごとに9問を解く。わからない問題は「わからない」で次へ進めます。
3. 級を解き終えるたびに「○級合格！ つぎは○級」または不合格の画面が出ます。答えあわせと解説も見られます。
4. 終了すると結果画面が出ます（最高合格級、受けた級の一覧、レーダーチャート、不合格の理由、次に学ぶとよいこと）。
5. 「結果を保存（CSV）」をおして、Teams の課題に提出する。

> **注意**：受験中のデータは保存されません。途中でブラウザを閉じたり再読み込みしたりすると、最初からやり直しになります（受験中に閉じようとすると確認が出ます）。

### 3-1. 提出のしかた（生徒の画面にも図付きで表示されます）

**PC・Chromebook**
1. 「結果を保存（CSV）」→ 「ダウンロード」フォルダーに保存される
2. Teams の課題で「作業を追加」→「このデバイスからアップロード」
3. 「提出」

**iPad・スマホ**
1. 「結果を保存（CSV）」→ 「ダウンロード」を選ぶ（または「共有メニューで保存・提出」→「“ファイル”に保存」）
2. 「ファイル」アプリの「ダウンロード」フォルダーに `ICT_` で始まるファイルができる
3. Teams の課題で「＋作業を追加」→「ファイル（参照）」から選ぶ
4. 「提出」

## 4. 提出されたCSVについて

### ファイル名
`ICT_<クラス>_<出席番号>_<受験開始の年月日-時分>.csv`（例：`ICT_5-1_07_20261111-0905.csv`）

### 中身
- UTF-8（BOM付き）なので、Excel でダブルクリックして開いても文字化けしません。
- 1行目が見出し、2行目以降は**受けた級ごとに1行**です。

| 列 | 内容 |
|---|---|
| class / number | クラス・出席番号 |
| startedAt | 受験開始日時 |
| device | 端末の種類（PC / Chromebook / iPad / スマホ） |
| startGrade | はじめた級（数字のみ。例：5、準2） |
| highestPassed | 最高合格級（合格がなければ「なし」） |
| grade | この行の級（準2級は「準2」、準1級は「準1」と書きます） |
| result | 合格／不合格 |
| total | 合計正解数（9問中） |
| operation / information / safety | 分野別の正解数（各3問中） |
| questions | 問題ごとの正誤（例：`g5-safety-01:1;g5-info-02:0;…`、1が正解） |
| elapsedSec | この級にかかった秒数 |
| mode | 本番／試作 |
| endReason | 終了の理由（不合格／1級合格／時間切れ／問題不足） |
| checkCode | 確認コード（下記） |

### 確認コード（書き換え対策）について

各行の `checkCode` は、その行の内容と、アプリに埋め込んだ文字列から計算した値（SHA-256 の先頭8文字）です。
生徒が CSV の点数や合否を書き換えると、確認コードが一致しなくなり、先生用ツールで警告が出ます。

> **重要：これは「書き換えの抑止」であり、完全な不正防止ではありません。**
> 計算に使う文字列はアプリの中に入っているため、知識のある人が調べれば、正しい確認コードを作り直すことは理論上可能です。
> また、別の人に代わりに受験してもらう、何度も受け直して良い結果だけを提出する、といった行為は防げません。
> 確認コードの不一致は「書き換えられた可能性がある」という目安として扱い、必要に応じて本人に確認したり、授業中にその場で提出させたりしてください。

## 5. 先生用ツール（teacher.html）

`dist/teacher.html` をブラウザで開き、提出された CSV ファイルを**まとめてドラッグ＆ドロップ**します（クリックしてファイルを選ぶこともできます）。

> ファイルは**このブラウザの中だけで処理**し、インターネットには一切送信しません。

表示されるもの：

1. **件数のまとめ**：ファイル数・受験者数・行数と、確認コードが一致しない行の数
2. **警告**：
   - 確認コードが一致しない行（書き換えの可能性） … 赤で表示
   - 読み込めなかったファイル（このテストのCSVではないもの）
3. **受験者の一覧**：クラス・番号・受験日時・端末・開始級・最高合格級・最後に受けた級と分野別点数・モード・終了理由
4. **まとめた CSV を保存**：読み込んだ全行を1つのCSVにして保存します（先頭に `fileName`（元のファイル名）と `checkOK`（確認コードの一致：OK／NG）の列が付きます）
5. **問題ごとの正答率**：正答率の低い順に表示。5人以上が解いた問題で、正答率30%未満を「難しすぎ？」、95%超を「易しすぎ？」として色付けします。問題の見直しに使ってください。
   - 確認コードが一致しない行は数えません。
   - 「試作モードの結果も集計に含める」のチェックを外すと、本番の結果だけで集計します。

## 6. Excel でまとめる方法（データの取得 → フォルダーから）

先生用ツールを使わずに、OneDrive の1つのフォルダーに集めたCSVを Excel で1つの表にまとめることもできます。
（Teams の課題に提出された各生徒のCSVファイルを、あらかじめ OneDrive の同じフォルダーに保存しておきます。）

1. 提出された CSV ファイルを、**1つのフォルダー**にまとめて保存する（OneDrive と同期しているフォルダーなら、PCのエクスプローラーから選べます）。ほかのファイルは入れないでください。
2. Excel で新しいブックを開き、**［データ］タブ →［データの取得］→［ファイルから］→［フォルダーから］** を選ぶ。
3. CSV を集めたフォルダーを選んで［開く］。
4. ファイルの一覧が出たら、**［結合］→［データの結合と変換］**（または［結合して読み込む］）を選ぶ。
5. 「ファイルの結合」画面で、
   - **元のファイル**：**65001: Unicode (UTF-8)** になっていることを確認（文字化けする場合はここを変更）
   - **区切り記号**：コンマ
   - 先頭のファイルの見出しが使われることを確認して［OK］
6. Power Query エディターが開いたら、そのまま［閉じて読み込む］。
   1つのシートに全員分の行がまとまります。先頭の `Source.Name` 列が元のファイル名です。
7. 提出が増えたら、フォルダーにCSVを追加して、**［データ］→［すべて更新］** をおすと表が更新されます。

> Excel での集計では**確認コードの照合はできません**。書き換えの確認は先生用ツールで行ってください。

まとめた表の使い方の例：
- 「最高合格級」の列でフィルターし、級ごとの人数を数える（ピボットテーブルが便利です）
- `operation` `information` `safety` の平均を比べ、クラス全体で弱い分野を見つける

## 7. 問題の追加と確認（AIで作った問題を人が確認してから使う）

問題は `src/questions/grade-1.json` 〜 `grade-8.json` に入っています。各問題には `status` があります。

| status | 意味 | 本番で出題 |
|---|---|---|
| `draft` | AIが作っただけ（未確認） | されない（試作モードでのみ出題） |
| `approved` | 人が確認済み | される |
| `rejected` | 使わない | されない |

流れ：**AIが生成 → 人が確認 → approved にして問題バンクへ → 本番で出題**

1. 問題の候補を作る（開発担当）：`npm run generate -- --grade 5 --field safety --type choice --count 5`
   → `questions/drafts/` に `draft` として保存されます（APIキーは環境変数 `ANTHROPIC_API_KEY` に設定。リポジトリには書きません）。
2. レビュー用ツールで確認する：`npm run dev` → ブラウザで `http://localhost:5173/scripts/review.html` を開く
   （`npm run build:review` で1つのHTMLファイル `dist-tools/scripts/review.html` にもできます）。
   - 問題のJSONファイルを読み込み、1問ずつ「承認」「却下」「編集」します。確認者名と日付が記録されます。
   - 確認が終わったら「結果をJSONで書き出す」。
3. 書き出したJSONを問題バンクに反映する：`npm run merge -- <書き出したファイル>`
   （同じ id の問題は上書きし、新しい問題は該当する級のファイルに追加します）
4. `npm test` で形式チェック（id の重複、正解番号の範囲、各級・各分野の問題数など）を行い、`npm run build` し直して配布します。

AIによる事前の点検結果（修正した問題、学校の環境によって言葉が違う問題の一覧）は [question-review.md](question-review.md) にまとめています。

確認のときに見るポイント：
- **正解が1つに決まるか**（ほかの選択肢も正解と言えてしまわないか）
- **事実として正確か**（とくに数字・用語・操作手順）
- その級の学年のめやすに合った言葉・内容か（8級〜6級はふりがなが付いているか）
- 特定の子どもや家庭を傷つける表現がないか

## 8. プライバシーと安全

- 名前・メールアドレスは扱いません。扱うのはクラスと出席番号だけです。
- 受験中・結果表示中に、外部への通信はしません（ビルドしたHTMLには、外部通信を禁止する設定〔Content-Security-Policy〕が入っています）。解析ツールやトラッキングも入っていません。
- 受験中のデータはブラウザのメモリ上にだけあり、ブラウザを閉じると消えます。
- 読み上げは、端末の中で音声を作る声だけを使います。端末にそのような日本語の声がない場合（一部の Chromebook など）、読み上げボタンは使えない表示になります。

## 9. 問題の目安の根拠

級の内容は、文部科学省「情報活用能力の体系表例」（ステップ1〜5）を参考に、次のように対応させています（目安です）。

| 級 | 学年のめやす | 体系表例のステップ（目安） |
|---|---|---|
| 8級・7級 | 小1・小2 | ステップ1 |
| 6級・5級 | 小3・小4 | ステップ2 |
| 4級・3級 | 小5・小6 | ステップ3 |
| 準2級 | 中1・中2 | ステップ4 |
| 2級 | 中3 | ステップ4 |
| 準1級 | 高校（「情報Ⅰ」程度） | ステップ5 |
| 1級 | 高校卒業〜大人 | ステップ5 |

出典：文部科学省「次世代の教育情報化推進事業（情報教育の推進等に関する調査研究）」成果報告書における「情報活用能力の体系表例」。
